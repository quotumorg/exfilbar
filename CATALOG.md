Source rules read: `plugin-catalog/README.md`, `website/docs/developer-guide/plugins/catalog-submission.md`, `scripts/validate_plugin_catalog.py`, `hermes_cli/plugin_validate.py`, `hermes_cli/plugins_manifest.py`, `.github/workflows/plugin-catalog-ci.yml`.

The offline checks compile selected unmodified validator definitions from local source. The YAML fixture reader deliberately supports only mappings and inline scalars used in these two files. It is not a general YAML validator. The full manager needs optional dependencies unavailable in the stdlib-only workflow.

Remaining admission steps, not performed here:

- Publish reviewable source under a real owner's repository; pin a real full commit SHA. Verify owner/contributor eligibility and settle licensing.
- Run `hermes plugins validate` and Plugin Doctor in a prepared environment, including the security scanner, isolated capability probe, no-core-override and private-import checks. The source-level test harness uses internal AST/reducer plumbing; review any scanner warnings about test fixtures separately from runtime.
- Run installed-Hermes end-to-end checks. The current integration tests simulate dispatch and never execute transfers.
- Submit an owner-controlled catalog PR with rule-13 disclosures; obtain maintainer review. Human merge is the catalog trust gate.

Checked on an installed Hermes v0.23.0 with Desktop: install scan verdict safe, chip, feed page and commands work. Profile switching and other Hermes versions are untested. Route labels display as `route 1`, including legacy ledger rows.
